# Промпт: добивочный тест по ошибкам

**Вход:** `progress/mistakes.jsonl` (выгрузка `GET /api/mistakes.jsonl?days=7`),
опционально период и число вопросов (по умолчанию 20).
**Выход:** `tests/drill/<ГГГГ-ММ-ДД>-<пользователь>.json`.

Смысл: не повторить те же вопросы — их и так вернёт FSRS, — а **зайти с других сторон**
в те места, где человек реально плавает.

---

## Шаги

1. Прочитать лог. Формат строки:

   ```json
   {"ts":"2026-11-08T09:12:00Z","item":"a2-01-0012","rule":"A2/01-aorist-conj1","tags":["aorist"],"answered":"αγόραζα","correct":false}
   ```

2. Посчитать долю ошибок **по тегам** и **по правилам**. Учитывать только то, где было
   хотя бы 5 попыток: на двух ответах статистики нет.

3. Посмотреть на сами неверные ответы в поле `answered` — это важнее процентов. Если человек
   на аорист трижды ответил формой παρατατικός, проблема не в «аористе вообще», а конкретно
   в различении вида. Тест надо строить против этого.

4. Взять 2–3 худшие темы, прочитать соответствующие правила в `source/rules/`.

5. Сгенерировать вопросы по схеме из `prompts/new-test.md` — формат, требования к
   дистракторам, `why` и греческому тексту те же. Отличия файла от обычного теста:

   ```json
   {
     "kind": "drill",
     "title": "Добивка: аорист 1-го спряжения",
     "user": "roman",
     "date": "2026-11-08",
     "items": [
       {
         "id": "drill-2026-11-08-0001",
         "rule": "A2/01-aorist-conj1",
         "type": "inflect",
         "prompt": "δουλεύω → αόριστος, 1-е лицо ед. ч.",
         "answer": "δούλεψα",
         "accept": ["δούλεψα"],
         "why": "-εύω → -εψ-: δούλεψα, а не δούλευσα.",
         "words": ["δουλεύω"],
         "tags": ["aorist", "verbs"]
       }
     ]
   }
   ```

   - `kind` всегда `"drill"`, файл лежит в `tests/drill/` и называется `<дата>-<пользователь>.json`;
   - у каждого вопроса свой `rule` — добивка собирает по нескольким правилам;
   - `id` начинается с `drill-<дата>-`, а не с `<уровень>-<правило>-`.

6. Прогнать `python3 tools/check-tests.py tests/drill/<файл>.json`.

7. Отчитаться: какие темы выбраны, какая была доля ошибок, какая именно путаница видна
   в ответах.

---

## Отличия от обычного теста

- **Другие слова.** Если ошибка была на `αγοράζω` — брать другие глаголы той же группы.
  Запоминание конкретной карточки вместо правила — главный риск, его надо обходить.
- **Другая формулировка.** Было `choice` — дать `inflect`. Узнавание среди вариантов и
  порождение формы с нуля проверяют разные вещи, и второе честнее.
- **Контраст в упор.** Если путаются две формы — ставить их рядом в одном вопросе, где
  выбор решается одним признаком (маркер времени, вид действия).
- **Сложность по месту.** Тема провалена целиком — начать с простого узнавания. Проседает
  только применение в контексте — не тратить вопросы на базу.
- **`id` с префиксом `drill-`**, чтобы не пересекаться с основной нумерацией:
  `drill-2026-11-08-0001`.

---

## Чего не делать

- Не копировать вопросы из основных тестов — это сделает FSRS.
- Не брать тему, где ошибок мало: добивочный тест на 95% правильных ответов — потерянное время.
- Не раздувать объём: 15–20 точных вопросов полезнее сорока разбавленных.
