## 2. Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Правила | Markdown + frontmatter, папки по уровням | Читается глазами, диффится в git, скармливается агенту |
| Слова | CSV по частям речи и уровням | У глагола, существительного и прилагательного разные колонки |
| Anki | Остаётся для слов, мост через TSV | Формат открытый (ZIP + SQLite), переписывать SRS и синхронизацию незачем |
| Генерация тестов | Офлайн, агентом в opencode, результат в git | Бесплатно, кривой греческий виден в ревью, в клиенте нет ключей |
| Повторение | FSRS (`ts-fsrs`) + лог ошибок для агента | Тот же алгоритм, что в Anki, плюс точечная добивка слабых мест |
| Приложение | Vite + TypeScript, SPA | Общий прогресс и статистика по всем темам сразу |
| Хранение прогресса | SQLite на домашнем сервере | Несколько пользователей, один прогресс на все устройства |
| Доступ | Браузер по локальной сети / Tailscale | Телефон и ноутбук работают с одной базой |

## 3. Архитектура

```
         репозиторий (git)                       домашний сервер
   ┌──────────────────────────┐          ┌──────────────────────────────┐
   │ source/rules/**/*.md     │          │  Node + Fastify              │
   │ source/words/**/*.csv    │ git pull │  ├── отдаёт собранный SPA    │
   │ tests/**/*.json          ├─────────►│  ├── читает контент с диска  │
   └──────────────────────────┘          │  ├── ts-fsrs (расписание)    │
              ▲                          │  └── SQLite: users, progress │
              │ генерация                └───────────────┬──────────────┘
   ┌──────────┴───────────┐                              │ HTTP
   │  агент в opencode    │                      ┌───────┴────────┐
   │  по prompts/*.md     │◄─────────────────────┤ браузер / PWA  │
   └──────────────────────┘   экспорт ошибок     │ ноутбук, телефон│
                                                 └────────────────┘
```

Ключевое решение: **контент — это данные, а не вход сборки.** Правила, слова и тесты
бэкенд читает с диска в рантайме. Добавить новый тест = `git pull` + перезапуск процесса,
без пересборки фронтенда.

## 4. Форматы данных

### 4.1 Правила — готово

`source/rules/<уровень>/<номер>-<тема>.md`. Формат зафиксирован и проверяется валидатором:

```yaml
---
id: A2/01-aorist-conj1
title: Αόριστος 1-го спряжения — основа на -σ-, -ξ-, -ψ-
level: A2
tags: [verbs, past, aorist]
requires: [A1/06-present-conj1]
source: verbs.pdf, с. 1–13
---
```

`id` — якорь, по которому тест ссылается на правило. Менять нельзя после того, как на него
начали ссылаться тесты.

### 4.2 Слова — привести к CSV

Сейчас есть три сырых файла. `b1_anki.txt` — самый ценный, там уже есть часть речи:

```
το αβγό / το αυγό	яйцо (Τρώω ένα αβγό - Я ем яйцо)	noun
αγαπάω & αγαπώ	любить (αγάπησα - я полюбил; Σ' αγαπώ - Я тебя люблю)	verb
```

Проблемы: перевод и пример слеплены в одной колонке, у глаголов нет основных форм отдельными
полями, варианты написания через `/` и `&` не разобраны.

Куда приводим:

```
source/words/
  B1/
    verbs.csv
    nouns.csv
    adjectives.csv
    other.csv        # наречия, предлоги, союзы, фразы
  A2/ …
```

**verbs.csv** — основные формы отдельными колонками, из них генерируются упражнения
«поставь в аорист», «переведи в будущее», «найди лишнюю форму»:

```csv
lemma,alt,ru,aorist,future,passive,passive_aorist,root,level,theme,example_gr,example_ru
αγαπάω,αγαπώ,любить,αγάπησα,θα αγαπήσω,αγαπιέμαι,αγαπήθηκα,αγαπ-,B1,feelings,Σ' αγαπώ.,Я тебя люблю.
γράφω,,писать,έγραψα,θα γράψω,γράφομαι,γράφτηκα,γραφ-,A2,school,Έγραψα ένα γράμμα.,Я написал письмо.
πηγαίνω,πάω,идти / ехать,πήγα,θα πάω,,,—,A2,travel,Πήγα στη δουλειά.,Я пошёл на работу.
```

**nouns.csv** — артикль отдельной колонкой, это сразу даёт упражнения «ο, η или το?»:

```csv
lemma,article,gen_sg,nom_pl,gen_pl,ru,root,level,theme
αβγό,το,του αβγού,τα αβγά,των αβγών,яйцо,,B1,food
αγάπη,η,της αγάπης,οι αγάπες,των αγαπών,любовь,αγαπ-,B1,feelings
πόλη,η,της πόλης,οι πόλεις,των πόλεων,город,πολ-,A2,city
```

**adjectives.csv** — три рода:

```csv
lemma,fem,neut,ru,comparative,root,level
αγαπημένος,αγαπημένη,αγαπημένο,любимый,πιο αγαπημένος,αγαπ-,B1
καλός,καλή,καλό,хороший,καλύτερος,καλ-,A1
```

Колонка `root` связывает однокоренные (`αγαπάω`, `αγάπη`, `αγαπημένος`). Это не только
красиво: генератор берёт из того же корня правдоподобные неправильные варианты, а случайные
дистракторы отбрасываются слишком легко.

### 4.3 Тесты — новый формат

`tests/<уровень>/<id правила>.json`, структура зеркалит `source/rules/`:

```json
{
  "rule": "A2/01-aorist-conj1",
  "title": "Αόριστος 1-го спряжения",
  "level": "A2",
  "items": [
    {
      "id": "a2-01-0012",
      "type": "choice",
      "prompt": "Χθες ___ ένα βιβλίο στο βιβλιοπωλείο.",
      "options": ["αγοράζω", "αγόρασα", "θα αγοράσω", "αγόραζα"],
      "answer": "αγόρασα",
      "why": "«Χθες» + однократное законченное действие → αόριστος. «αγόραζα» — παρατατικός, это «покупал регулярно».",
      "words": ["αγοράζω", "βιβλίο"],
      "tags": ["aorist", "time-markers"]
    },
    {
      "id": "a2-01-0013",
      "type": "inflect",
      "prompt": "γράφω → αόριστος, 1-е лицо ед. ч.",
      "answer": "έγραψα",
      "accept": ["έγραψα"],
      "why": "-φω → -ψα; слогов два, поэтому приращение έ-.",
      "words": ["γράφω"],
      "tags": ["aorist", "augment"]
    }
  ]
}
```

Три поля делают всю работу:

- **`rule`** — по нему кнопка «Правило» подтягивает нужный `.md`;
- **`why`** — разбор конкретно этой ошибки, а не всего правила целиком;
- **`tags`** — по ним считается статистика «аорист — 60% ошибок» и собираются добивочные тесты.

Типы в порядке внедрения:

| `type` | Что делает | Данные |
|---|---|---|
| `choice` | мультивыбор | правило + слова |
| `inflect` | «поставь в аорист / во мн. число», ввод с клавиатуры | формы из CSV |
| `cloze` | вписать пропущенное слово в предложение | слова |
| `article` | ο / η / το | `nouns.csv` |
| `translate` | RU → GR | любой словарь |

Первых двух хватает на старт — это 80% пользы при минимуме кода.

**Ввод с клавиатуры и ударения.** Поле `accept` — список принимаемых вариантов. Сравнение
нормализуем: убираем ударения, приводим конечную `ς` к `σ`, схлопываем регистр. Иначе
на телефоне без греческой раскладки с ударениями будет мучение. Но если ответ отличался
только ударением — показываем мягкое «правильно, но ударение: **έ**γραψα».

### 4.4 Валидатор тестов

`tools/check-tests.py` — по образцу уже работающего `check-rules.py`. Ловит:

- `rule` указывает на несуществующее правило;
- `answer` не входит в `options`;
- дубли `id` внутри файла и между файлами;
- неизвестный тег (общий словарь тегов с `check-rules.py`);
- греческое слово с латиницей/кириллицей внутри, символ `µ` вместо `μ`;
- многосложное слово без ударения (предупреждение);
- пустой `why`.

Это главная страховка при генерации агентом: сгенерировал → прогнал валидатор → глазами
посмотрел спорное → закоммитил.

## 5. Генерация тестов

Генерируем офлайн агентом в opencode. Промпты лежат в репозитории, чтобы результат был
воспроизводимым, а не зависел от того, как сформулировал в этот раз.

```
prompts/
  new-test.md      # сгенерировать тест по правилу
  normalize-words.md  # сырой txt → CSV по частям речи
  drill.md         # добивочный тест по логу ошибок
```

Промпт — обычный markdown, его можно просто скормить любому агенту. Сверху — тонкая обёртка
под opencode (`.opencode/command/`), чтобы вызывалось одной командой; сам текст промпта
остаётся в `prompts/`, поэтому не привязан к конкретному инструменту.

Содержание `prompts/new-test.md` в двух словах: прочитать файл правила целиком, брать лексику
только из `source/words/`, выдать N вопросов в описанном JSON, заполнить `why` разбором именно
этой ошибки, дистракторы брать грамматически правдоподобные (соседние времена, тот же корень),
прогнать `tools/check-tests.py` и починить, что не прошло.

Полный текст — в самих файлах промптов, здесь его дублировать не нужно.

Генерировать тесты пока не начинаем — сначала формат, валидатор и один эталонный тест руками.
Без эталона агент будет выдавать каждый раз разное.

## 6. Повторение ошибок

Две вещи работают вместе.

### FSRS — расписание

Библиотека `ts-fsrs`, тот же алгоритм, что в современном Anki. На вход состояние карточки
и оценка ответа, на выход — дата следующего показа. Считаем **на сервере**, не в браузере:
тогда прогресс один на все устройства и не зависит от чистки данных в браузере.

Оценка выводится автоматически из ответа, спрашивать пользователя «легко/трудно» не нужно:

| Что произошло | Рейтинг FSRS |
|---|---|
| Ошибся | `Again` |
| Ответил верно, но подглядел правило | `Hard` |
| Ответил верно | `Good` |
| Ответил верно и быстро (меньше ~3 с) | `Easy` |

Единица повторения — **вопрос** (`item.id`), а не правило. Правило — это группировка для
статистики.

### Лог ошибок — работа над слабыми местами

Каждый ответ пишется в таблицу `attempts`. Выгрузка:

```
GET /api/mistakes.jsonl?user=roman&days=7
```

```jsonl
{"ts":"2026-11-08T09:12:00Z","item":"a2-01-0012","rule":"A2/01-aorist-conj1","tags":["aorist"],"answered":"αγόραζα","correct":false}
{"ts":"2026-11-08T09:13:10Z","item":"a2-09-0041","rule":"A2/09-genitive","tags":["genitive","neuter"],"answered":"του παιδί","correct":false}
```

Дальше агенту: «посмотри мои ошибки за неделю и собери тест на то, что проседает». Он видит,
что путается родительный среднего рода и аорист с приращением, и генерирует точечный тест
**с новых сторон** — другие слова, другие формулировки, — а не повтор тех же вопросов.

Этого нет ни в Anki, ни в готовых приложениях, и ровно ради этого стоит писать своё.

## 7. Несколько пользователей

Профили с отдельным прогрессом. Сценарий — домашний: несколько человек, каждый со своего
устройства, общий контент и разные кривые повторений.

### Модель

```sql
CREATE TABLE users (
  id         INTEGER PRIMARY KEY,
  name       TEXT UNIQUE NOT NULL,     -- roman, anna
  display    TEXT NOT NULL,            -- Роман
  pin_hash   TEXT,                     -- NULL = вход без PIN
  level      TEXT DEFAULT 'A2',        -- текущий уровень
  created_at TEXT NOT NULL
);

CREATE TABLE progress (
  user_id    INTEGER NOT NULL REFERENCES users(id),
  item_id    TEXT NOT NULL,            -- a2-01-0012
  due        TEXT NOT NULL,
  stability  REAL, difficulty REAL,
  reps       INTEGER, lapses INTEGER,
  state      INTEGER,                  -- состояние FSRS
  last_review TEXT,
  PRIMARY KEY (user_id, item_id)
);

CREATE TABLE attempts (
  id        INTEGER PRIMARY KEY,
  user_id   INTEGER NOT NULL REFERENCES users(id),
  item_id   TEXT NOT NULL,
  rule      TEXT NOT NULL,
  tags      TEXT NOT NULL,             -- JSON-массив
  answered  TEXT,
  correct   INTEGER NOT NULL,
  ms        INTEGER,                   -- время на ответ
  peeked    INTEGER DEFAULT 0,         -- смотрел ли правило
  ts        TEXT NOT NULL
);
```

Контент (правила, слова, тесты) общий для всех — он в файлах, не в базе. В базе только то,
что у каждого своё.

### Вход

Экран выбора профиля: плитки с именами + «добавить профиль». Опционально 4-значный PIN,
чтобы дети не открывали чужой прогресс. После выбора — подписанная cookie на год, больше
не спрашиваем.

Это **не защита**, а «кто ты из нас». Логинов с паролями, восстановления почты и ролей здесь
не нужно. Если сервис когда-нибудь выставится наружу — защита делается снаружи
(Tailscale или reverse proxy с basic-auth), а не переписыванием этой части.

### Что это даёт сверх разделения прогресса

- переключение профиля без выхода из приложения (полезно, если учитесь вдвоём с одного ноутбука);
- экран сравнения: кто сколько вопросов закрыл за неделю — неожиданно хорошо работает как мотивация;
- у каждого свой уровень: один на A2, другой на B1, контент один и тот же.

### API

```
GET  /api/users                       → список профилей (без PIN-хэшей)
POST /api/users          {name, pin?} → создать
POST /api/session        {name, pin?} → cookie
POST /api/session/logout

GET  /api/content/rules               → список правил с frontmatter
GET  /api/content/rules/:id           → markdown правила
GET  /api/content/tests               → манифест тестов

GET  /api/queue?rule=A2/01&limit=20   → очередь: просроченные + новые
POST /api/review  {itemId, correct, ms, peeked}
                                      → записывает attempt, двигает FSRS, отдаёт следующий показ
GET  /api/stats                       → по тегам, по правилам, за период
GET  /api/mistakes.jsonl?days=7       → экспорт для агента
```

Всё под текущим пользователем из cookie — `user_id` в запросах не передаётся, чтобы нельзя
было случайно записать в чужой прогресс.

## 8. Домашний сервер

Да, ставить на домашний сервер — правильно, и с несколькими пользователями это уже не
удобство, а необходимость: прогресс должен жить в одном месте, иначе телефон и ноутбук
разъедутся.

### Что разворачивается

Один процесс Node: отдаёт собранный фронтенд как статику и обслуживает `/api`.
Рядом — файл SQLite и папка с контентом. Никаких внешних сервисов, Postgres и Redis здесь
не нужны: нагрузка — несколько человек.

```yaml
# docker-compose.yml
services:
  greek:
    build: .
    restart: unless-stopped
    ports: ["8080:8080"]
    volumes:
      - ./data:/app/data           # greek.db — прогресс, бэкапить это
      - ./content:/app/content:ro  # git-репозиторий с правилами и тестами
    environment:
      - SESSION_SECRET=…
```

Альтернатива без Docker — systemd-юнит плюс `npm ci && npm run build`. Docker удобнее тем,
что обновление сводится к `git pull && docker compose up -d --build`.

### Доступ и HTTPS — важный момент

Service worker (то есть офлайн и «Добавить на экран Домой» на телефоне) работает **только
в защищённом контексте**. `localhost` считается защищённым, а `http://192.168.1.50:8080`
— нет. То есть по голому IP в локальной сети приложение в браузере откроется и будет
работать, но PWA и офлайна не будет.

Варианты, от простого к сложному:

1. **Tailscale Serve** — поднимает перед сервисом валидный HTTPS-сертификат на имя вида
   `greek.<tailnet>.ts.net`, ничего не нужно настраивать и никакие порты наружу не открываются.
   Работает и дома, и из города. Рекомендую это.
2. **Caddy + свой домен, DNS-01** — если домен уже есть. Let's Encrypt через DNS-челлендж,
   порты наружу тоже не нужны.
3. **mkcert** — локальный центр сертификации, сертификат ставится на каждое устройство руками.
   Работает, но при добавлении нового телефона придётся повторять.
4. **Без HTTPS** — по IP в локальной сети. Нормально для старта, PWA просто отложить.

### Обновление контента

Поскольку бэкенд читает контент с диска, новый тест доезжает так:

```
локально: сгенерировал → check-tests.py → git push
на сервере: git pull && docker compose restart greek
```

Пересборка фронтенда не нужна — это окупится, когда тесты начнут появляться пачками.

### Бэкап

Бэкапить нужно ровно `data/greek.db` — всё остальное в git. Достаточно крона с
`sqlite3 greek.db ".backup /backup/greek-$(date +%F).db"` и чисткой старше месяца.

## 9. План работы

Этапы идут по зависимостям: каждый опирается на предыдущий и даёт результат, который можно
пощупать.

### Этап 1 — нормализовать словарь

- `prompts/normalize-words.md` + скрипт: `b1_anki.txt` → `source/words/B1/{verbs,nouns,adjectives,other}.csv`
- Разделить слепленные «перевод (пример)» на `ru` / `example_gr` / `example_ru`
- Разобрать варианты через `/` и `&` в колонку `alt`
- Дозаполнить формы глаголов (`aorist`, `future`) — часть уже есть в примерах, остальное агентом
