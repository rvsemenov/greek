# Приложение для изучения греческого — варианты архитектуры

Документ-решение: что из чего собирать, какие форматы файлов выбрать и в каком порядке
это строить. В конце — рекомендация и пошаговый план.

---

## 1. Что уже есть

| Что | Где | Оценка |
|---|---|---|
| Источник по глаголам | `source/verbs.pdf` | Исходник, но не машиночитаемый |
| 6 тестов | `tests/*.html` | Самодостаточные одностраничники: мультивыбор, тёмная тема, блок правила сверху |
| Данные тестов | внутри HTML (`const ROWS = [...]`) | Дублируются между файлами, нельзя переиспользовать |
| Прогресс / повторение | — | Нет. Закрыл вкладку — всё забыто |

**Что это значит.** Формат «один HTML-файл, открыл и работает» — сильная сторона: работает
офлайн, на телефоне, без сборки и сервера. Терять её не надо. Проблемы ровно две:
данные вперемешку с кодом и нет памяти об ошибках. Всё дальнейшее — про то, как это
починить, не ломая удобство.

## 2. Четыре развилки

Весь выбор сводится к четырём независимым вопросам. Их можно решать по отдельности.

1. **Где живут правила** → Markdown в репозитории (см. §4)
2. **Где живут слова** → Anki + плоские файлы в репозитории (см. §5)
3. **Кто и когда генерирует тесты** → Claude Code офлайн, результат в git (см. §6)
4. **Где живёт прогресс и повторение ошибок** → главная развилка, см. §7

## 3. Anki — да, формат открытый

Коротко, раз был вопрос:

- **Приложение** — открытый исходный код (AGPL), Anki Desktop / AnkiDroid.
- **`.apkg`** — это обычный ZIP, внутри база SQLite (`collection.anki2` / `.anki21`) плюс медиа.
  Распаковывается и читается скриптом без всяких API.
- **CSV/TSV импорт-экспорт** — встроенный. Самый надёжный мост в обе стороны.
- **`genanki`** (Python) — библиотека, собирает `.apkg` с нуля: свои типы заметок, поля, шаблоны.
- **AnkiConnect** — аддон, поднимает локальный HTTP API на `localhost:8765`. Позволяет из скрипта
  добавлять заметки, искать карточки, читать статистику — пока Anki запущен на компьютере.
- **FSRS** — современный алгоритм интервальных повторений, встроен в Anki и включён по умолчанию
  в свежих версиях. Та самая «не знаешь — попадётся снова», но заметно умнее старого SM-2.
- **Шаблоны карточек** — это HTML + CSS + немного JS. Кнопка «показать правило» через
  `<details>` работает прямо внутри Anki.

**Вывод: слова оставляем в Anki.** Переписывать интервальные повторения и мобильную
синхронизацию с нуля — это месяцы работы ради того, что уже есть и работает.

Чего Anki делать не умеет (и ради чего нужно своё приложение):
- тест как **сессия по теме** («15 вопросов на аорист»), а не поштучная очередь карточек;
- мультивыбор с разбором ошибки и ссылкой на конкретное правило;
- аналитика «на чём именно я сыплюсь» по грамматическим категориям;
- генерация упражнений из слов на лету.

## 4. Правила: Markdown с frontmatter

`source/rules/A1|A2|B1|B2/*.md`. Markdown, не HTML — он читается глазами, рендерится где угодно,
отлично ложится в git diff, и его удобно скармливать AI.

Ключевой элемент — frontmatter: он даёт каждому правилу **стабильный `id`**, по которому тест
потом ссылается на правило. Без этого кнопка «почему неправильно» не сделается нормально.

```markdown
---
id: A2/05-aorist
title: Αόριστος — простое прошедшее
level: A2
tags: [verbs, tenses, past]
requires: [A1/08-present]
---

## Когда используется

Однократное законченное действие в прошлом: **Χθες αγόρασα ένα βιβλίο.**

## Образование

| Ενεστώτας | Αόριστος | Θέμα |
|---|---|---|
| γράφω | έγραψα | γραψ- |
| αγοράζω | αγόρασα | αγορασ- |
| μιλάω | μίλησα | μιλησ- |

## Маркеры

χθες, πέρυσι, πριν δύο μέρες, ξαφνικά

## Типичные ошибки

- Путают с παρατατικός: *έγραφα* (писал, долго) ≠ *έγραψα* (написал, один раз).
```

Правило `requires` позволяет позже сделать «не давать B1-тест, пока A2 не закрыт» — но это
на будущее, сразу не нужно.

> Папку можно назвать `правила` кириллицей — на macOS это работает. Но латинское `rules`
> безопаснее для скриптов, URL и GitHub Pages. Рекомендую `rules`.

## 5. Слова: отдельные файлы по частям речи

Тут был прямой вопрос — да, **глаголы стоит отделить**, но причина не в том, что их больше,
а в том, что **у разных частей речи разный набор колонок**. Пихать их в одну таблицу — значит
получить таблицу с половиной пустых ячеек.

```
source/words/
  A2/
    verbs.csv        # основные формы
    nouns.csv        # род + падежи + множественное
    adjectives.csv   # три рода
    other.csv        # наречия, предлоги, союзы, устойчивые фразы
  B2/
    ...
```

**Формат — CSV/TSV, не Markdown.** Причина простая: это ровно то, что импортируется в Anki
и экспортируется из него без конвертеров.

### verbs.csv

```csv
lemma,ru,aorist,future,passive,passive_aorist,level,theme,example_gr,example_ru
γράφω,писать,έγραψα,θα γράψω,γράφομαι,γράφτηκα,A2,school,Έγραψα ένα γράμμα.,Я написал письмо.
αγοράζω,покупать,αγόρασα,θα αγοράσω,αγοράζομαι,αγοράστηκα,A2,shopping,Αγόρασα ψωμί.,Я купил хлеб.
μιλάω,говорить,μίλησα,θα μιλήσω,—,—,A2,social,Μιλάω ελληνικά.,Я говорю по-гречески.
πηγαίνω,идти / ехать,πήγα,θα πάω,—,—,A2,travel,Πήγα στη δουλειά.,Я пошёл на работу.
```

Основные формы — это и есть главная ценность: из них генерируются упражнения
«поставь в аорист», «переведи в будущее», «найди лишнюю форму». Без них тест по глаголам
может быть только на перевод.

### nouns.csv

```csv
lemma,article,gen_sg,nom_pl,gen_pl,ru,level,theme
παιδί,το,του παιδιού,τα παιδιά,των παιδιών,ребёнок,A2,family
γυναίκα,η,της γυναίκας,οι γυναίκες,των γυναικών,женщина,A2,family
άντρας,ο,του άντρα,οι άντρες,των αντρών,мужчина,A2,family
πόλη,η,της πόλης,οι πόλεις,των πόλεων,город,A2,city
```

Артикль отдельной колонкой — тогда появляется целый класс упражнений «ο, η или το?»,
а это самая частая ошибка на A2.

### Однокоренные слова

Раз в Anki уже собраны однокоренные — стоит сохранить эту связь. Два варианта:

- колонка `root` (`γραφ-`) — просто и достаточно, группирует семью слов;
- колонка `family` со списком через `;` — точнее, но руками тяжелее поддерживать.

Рекомендую `root`: генератор тестов сможет делать упражнения «собери семью слов» и
подбирать правдоподобные неправильные варианты из того же корня (это заметно усложняет тест
в хорошем смысле — случайные дистракторы слишком легко отбрасываются).

### Мост с Anki

```
Anki → Export (Notes in Plain Text) → source/words/A2/verbs.csv   # разово, забрать нажитое
source/words/**.csv → genanki / Anki Import                        # когда AI добавил новые слова
```

Держать источником правды репозиторий, а Anki — потребителем. Тогда AI видит весь словарь
и может генерировать тесты именно по выученным словам.

## 6. Генерация тестов: офлайн, а не в рантайме

Два подхода:

| | **Офлайн (Claude Code в репозитории)** | **Рантайм (вызов API из приложения)** |
|---|---|---|
| Стоимость | Ноль сверх подписки | Платные токены на каждый тест |
| Качество | Можно прочитать и поправить перед коммитом | Что сгенерировалось, то и получил |
| Ошибки в греческом | Видны в ревью | Уедут в тест незамеченными |
| Офлайн на телефоне | Работает | Нужен интернет и ключ в клиенте |
| Бесконечность вопросов | Ограничена сгенерированным | Бесконечно |

**Рекомендация — офлайн.** Приложение остаётся статикой без секретов, тесты лежат в git,
кривой вопрос можно поправить руками. Бесконечность на практике не нужна: 60–80 вопросов
на тему с рандомизацией порядка и вариантов хватает надолго, а новые генерируются одной
командой.

Правильное место для этого — **скилл Claude Code** в репозитории:

```
.claude/skills/new-test/SKILL.md
```

Чтобы «сгенерируй тест по аористу на 40 вопросов» работало одной фразой: скилл знает, где
правила, где слова, в какой формат писать и как проверять результат.

### Формат одного вопроса

```json
{
  "id": "a2-aorist-0012",
  "rule": "A2/05-aorist",
  "type": "choice",
  "prompt": "Χθες ___ ένα βιβλίο στο βιβλιοπωλείο.",
  "options": ["αγοράζω", "αγόρασα", "θα αγοράσω", "αγόραζα"],
  "answer": "αγόρασα",
  "why": "«Χθες» + однократное законченное действие → αόριστος. «αγόραζα» — παρατατικός, это «покупал регулярно».",
  "words": ["αγοράζω", "βιβλίο"],
  "level": "A2",
  "tags": ["aorist", "time-markers"]
}
```

Три поля делают всю работу:
- **`rule`** — по нему кнопка «Правило» подтягивает нужный `.md`;
- **`why`** — объяснение конкретно этой ошибки, а не всего правила целиком;
- **`tags`** — по ним считается статистика «аорист — 60% ошибок» и генерируются добивочные тесты.

### Типы упражнений

| `type` | Что делает | Откуда данные |
|---|---|---|
| `choice` | мультивыбор | правило + слова |
| `cloze` | вписать форму с клавиатуры | слова (формы) |
| `inflect` | «поставь в аорист / во мн. число» | `verbs.csv`, `nouns.csv` |
| `article` | ο / η / το | `nouns.csv` |
| `translate` | RU → GR и обратно | любой словарь |
| `transform` | «перепиши в прошедшем» | правило |
| `error` | найти ошибку в предложении | правило |
| `match` | сопоставить пары | слова |

Начинать стоит с `choice` + `cloze` + `inflect` — это 80% пользы при минимуме кода.

## 7. Повторение ошибок — главный выбор

Четыре варианта, от простого к мощному.

### Вариант A — Leitner в localStorage

Пять «коробок» с интервалами 10 минут / 1 / 3 / 7 / 21 день. Ответил правильно → коробка выше,
ошибся → вернулся в первую. Состояние — `localStorage`.

- **+** ~30 строк кода, понятно до последней строчки, работает в текущих одностраничниках
- **−** привязано к одному браузеру, не синхронизируется, прогресс теряется при чистке данных
- **Когда:** чтобы заработало сегодня

### Вариант B — FSRS через `ts-fsrs`

npm-пакет `ts-fsrs` — тот же алгоритм, что в Anki. На вход карточка и оценка, на выход дата
следующего показа. Состояние в `IndexedDB` + кнопка «экспортировать прогресс» в JSON.

- **+** интервалы реально оптимальные, не сильно сложнее Leitner
- **−** нужна сборка (npm/Vite), состояние всё ещё локальное
- **Когда:** как только тестов станет больше трёх

### Вариант C — ошибки уезжают в Anki

Ошибся в тесте → приложение через AnkiConnect создаёт карточку в колоде «Грамматика».
Повторение живёт целиком в Anki.

- **+** одна очередь повторений на всё, синхронизация и телефон бесплатно
- **−** AnkiConnect работает только когда Anki открыт на компьютере; грамматические вопросы
  в формате карточки выглядят куце
- **Когда:** если не хочется двух мест с прогрессом

### Вариант D — лог ошибок в репозитории + AI ⭐

Приложение пишет `progress/mistakes.jsonl` (экспорт одной кнопкой либо запись напрямую,
если крутить локальный dev-сервер):

```jsonl
{"ts":"2026-11-06T09:12:00Z","id":"a2-aorist-0012","rule":"A2/05-aorist","tags":["aorist"],"answered":"αγόραζα","correct":false}
{"ts":"2026-11-06T09:13:10Z","id":"a2-articles-0041","rule":"A2/02-articles","tags":["article","neuter"],"answered":"η","correct":false}
```

И дальше: **«посмотри мои ошибки за неделю и собери тест на то, что проседает»**. AI видит,
что путается средний род и аорист неправильных глаголов — и генерирует точечный тест
именно по этому, с новыми примерами, а не повтором тех же вопросов.

- **+** это то, чего нет ни в Anki, ни в любом готовом приложении: слабые места не просто
  повторяются, а **разбираются с новых сторон**
- **−** требует, чтобы ты периодически запускал генерацию (не автомат)
- **Когда:** как надстройка над B. Это и есть главная причина писать своё приложение

**Рекомендация: B + D.** FSRS держит механику «не знаешь — вернётся», лог ошибок даёт
осмысленную работу над слабыми местами. A — как первый шаг на сегодня, C — опционально позже.

## 8. Три варианта реализации приложения

### Вариант 1 — развить то, что есть: HTML + внешний JSON

Данные выносятся из HTML в `tests/*.json`, один общий `app.js` их загружает.

- **+** минимальный шаг от текущего состояния, не выкидывается ничего
- **+** без сборки, без npm
- **−** `fetch()` локального JSON не работает по `file://` — нужен `python3 -m http.server`
  либо хостинг
- **−** на троих-четверых тестах нормально, на двадцати начнёт разваливаться

### Вариант 2 — Vite + TypeScript, сборка в статику ⭐

Один SPA: список тем → сессия → разбор ошибок → статистика. Markdown-правила рендерятся
через `marked`, повторения через `ts-fsrs`, сборка в статику на GitHub Pages, на телефоне —
«Добавить на экран Домой» (PWA, работает офлайн).

- **+** один код для всех тестов, нормальный рост
- **+** честный PWA на телефоне с офлайном
- **+** TypeScript ловит кривые JSON-тесты на этапе сборки
- **−** нужен Node и шаг сборки
- **−** полдня на каркас

### Вариант 3 — Vite + build-шаг, собирающий одностраничники

Разработка как в варианте 2, но на выходе — по-прежнему самодостаточные `.html` с зашитыми
внутрь данными (`vite-plugin-singlefile`). Можно кинуть файл в Telegram, открыть с флешки, из
iCloud, без сервера.

- **+** сохраняет ровно то, что ценно в текущем подходе
- **−** общий прогресс между файлами сложнее (у каждого файла свой `localStorage` по пути)

**Рекомендация — вариант 2.** Общий прогресс и статистика по всем темам сразу — это то, ради
чего всё затевается, а в варианте 3 именно это и ломается. Самодостаточные файлы остаются
доступны как экспорт, если понадобится.

## 10. План по шагам

Каждый шаг даёт работающий результат сам по себе — можно остановиться на любом.

**Шаг 1 — вытащить данные из PDF (полдня).**
`source/verbs.pdf` → `source/words/A2/verbs.csv` + 3–5 правил в `source/rules/A2/*.md`.
Это разовая ручная работа с AI, но после неё всё остальное генерируется автоматически.

**Шаг 2 — экспорт из Anki (час).**
Выгрузить существующие колоды в CSV, разложить по частям речи и уровням. Теперь у AI есть
весь словарь, и тесты строятся на **уже выученных** словах — это принципиально другое
качество упражнений, чем случайная лексика.

**Шаг 3 — каркас приложения (полдня).**
Vite + TS, экран списка тем из `manifest.json`, сессия, кнопка «Правило» с рендером `.md`,
Leitner в `localStorage`. Текущие тесты переезжают в JSON.

**Шаг 4 — FSRS и статистика (полдня).**
`ts-fsrs` вместо Leitner, экран «слабые места» по тегам, экспорт `mistakes.jsonl`.

**Шаг 5 — скиллы генерации (час).**
`.claude/skills/new-test` — чтобы новый тест делался одной фразой, а не разговором на
двадцать сообщений.

**Шаг 6 — на телефон (час).**
GitHub Pages (приватный репозиторий + Pages, либо публичный — ничего секретного там нет),
манифест PWA, «Добавить на экран Домой».

Опционально: мост с Anki через AnkiConnect, озвучка (на macOS есть греческий голос:
`say -v Melina "καλημέρα"` — можно нагенерировать mp3 к словам).

## 11. Если писать не хочется: готовые решения

Честно — ни одно не закрывает связку «мои правила + мои слова + AI-тесты + разбор ошибки».
Но для справки:

| Решение | Что даёт | Чего не хватает |
|---|---|---|
| **Anki + аддоны** | SRS, мобильность, синхронизация | нет тестов по темам с разбором |
| **RemNote** | заметки и SRS в одном месте | закрытый формат, свои правила не версионируются |
| **Obsidian + Spaced Repetition** | md-файлы + повторения в одной папке | только карточки, нет мультивыбора и статистики по тегам |
| **Clozemaster** | греческие предложения с пропусками, много | чужая лексика, не связано с твоими правилами |
| **Quizlet / Memrise** | готовые наборы | вообще не про грамматику уровня B1+ |

Разумная комбинация без своего кода: **Anki для слов + Obsidian для правил**. Но AI-генерация
тестов по собственному логу ошибок — это то, чего там нет ни в каком виде, и ровно это и есть
смысл своего приложения.

## 12. Итог одной страницей

| Вопрос | Решение |
|---|---|
| Правила | Markdown + frontmatter с `id`, папки по уровням |
| Слова | CSV по частям речи и уровням; глаголы отдельно — у них свои колонки |
| Anki | Остаётся для слов. Формат открытый, мост через CSV. Не переписывать |
| Тесты | JSON, генерируются офлайн через Claude Code, лежат в git |
| «Показать правило» | Поле `rule` в вопросе + поле `why` с разбором именно этой ошибки |
| Повторение | `ts-fsrs` (тот же алгоритм, что в Anki) + лог ошибок для AI |
| Приложение | Vite + TS → статика → GitHub Pages → PWA на телефоне |
| Главная фишка | `mistakes.jsonl` → AI собирает точечный тест по слабым местам |

**Старт:** шаги 1–3 (≈1,5 дня) дают рабочую версию. Остальное наращивается по мере надобности.
